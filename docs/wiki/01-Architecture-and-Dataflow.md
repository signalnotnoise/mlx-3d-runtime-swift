# Architecture and dataflow

`textToMesh` and TripoSR image-to-mesh each return one `Mesh` (`Sources/MLX3DRuntime/Mesh.swift:5-16`). `textToMeshBatch` and Shap-E image-to-mesh return one `Mesh` per batch row. Sibling modules are called, not reimplemented.

## Text to mesh

`MLX3DRuntime.textToMesh` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:196-210`) builds a throwaway `MLX3DSession` and awaits that session's `textToMesh` (`Sources/MLX3DRuntime/MLX3DSession.swift:117-136`), which samples one mesh. `textToMeshBatch` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:213-229`) takes `batchSize` and returns every row (`Sources/MLX3DRuntime/MLX3DSession.swift:140-163`). The session rejects an illegal grid size, loads or reuses `ShapERuntime` for the bundle and BPE key, and awaits `generate` with the fields from `TextToMeshOptions` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:31-39`): guidance 15, 64 steps, grid 128, query batch 65536, seed 0, maximum grid 512, CPU marching cubes, and `progressInterval` 0. The single-mesh call passes batch size 1. The throwaway session is dropped when the call returns, so the static API still loads on every call.

`mesh(from:)` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:500-505`) copies `verticesArray()` and `facesArray()`. `rgbColors` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:507-523`) turns Shap-E RGBA (`count` divisible by 4) into packed RGB and drops the fourth component. An empty face list throws `emptyMesh` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:466-475`). A non-nil progress handler is adapted in `shapEProgress` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:478-498`). Nil stays nil, so Shap-E does not extract partial meshes. `progressInterval` greater than zero is what opts into those meshes.

Shap-E's latent, diffusion, and SDF sampler are external. This file does not name their tensor ranks.

## Image to mesh

`imageToMesh(imageURL:)` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:241-256`) rejects an illegal grid size before it checks the weights file, then calls `ImageTensor.rgb` (`Sources/MLX3DRuntime/ImageTensor.swift:20-31`). It does not run `foregroundCutout` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:230-232`). The static image methods do not consult `MLX3DSession`.

`imageToMesh(cgImage:)` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:268-303`) optionally calls `foregroundCutout` (`Sources/MLX3DRuntime/ImageBackgroundRemoval.swift:82-88`) and then `ImageTensor.rgb(cgImage:)` (`Sources/MLX3DRuntime/ImageTensor.swift:34-45`). `applyForegroundCutout` defaults to true and `foregroundRatio` to 0.85 (`Sources/MLX3DRuntime/MLX3DRuntime.swift:169-170`). `cutoutFailurePolicy` defaults to `.strict` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:171-171`). `.fallbackToOriginal` is the Mesquette behavior: nil or a thrown error logs and the original image is composited (`Sources/MLX3DRuntime/MLX3DRuntime.swift:411-423`). The white-background `removeBackground` (`Sources/MLX3DRuntime/ImageBackgroundRemoval.swift:38-70`) is not on this path.

`ImageTensor` draws into a `side` by `side` RGBA bitmap, fills `background` first, then either aspect-fits or stretches the source, and flips Y so row 0 is the top (`Sources/MLX3DRuntime/ImageTensor.swift:103-125`). The returned tensor is `[1, side, side, 3]` float RGB in `0...1`. Default `side` is 512, default background is 0.5, and default resize is aspect-fit (`Sources/MLX3DRuntime/ImageTensor.swift:21-24`, `Sources/MLX3DRuntime/MLX3DRuntime.swift:164-168`). `stretch` is the draw Mesquette's previous TripoSR facade used.

`imageToMesh(image:)` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:357-397`) again checks the grid, then loads `TripoSRModel` weights, accepts `[H, W, 3]` or `[1, H, W, 3]` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:533-554`), calls `forwardTriplanes`, and passes the triplanes to `TripoSRMeshing.extract` (`Sources/MLX3DRuntime/TripoSRMeshing.swift:6-53`). This repo does not read or check the triplane shape. The sibling README's `[1, 3, 64, 64, 40]` figure is a sibling measurement from public `triposr-mlx-swift` at `51994056febf3be5ed726e89de169037a2fbf6a6`, not a check in this package.

`TripoSRMeshing` places the cube on `[-radius, radius]` (`Sources/MLX3DRuntime/TripoSRMeshing.swift:22-23`). Density positions are generated per batch (`Sources/MLX3DRuntime/VolumeGrid.swift:30-50`, `Sources/MLX3DRuntime/TripoSRMeshing.swift:68-78`) and stored as one float per point (`Sources/MLX3DRuntime/TripoSRMeshing.swift:55-96`). Default batch size is 8192 (`Sources/MLX3DRuntime/MLX3DRuntime.swift:166`). Grids outside 2...512 are rejected before that allocation (`Sources/MLX3DRuntime/VolumeGrid.swift:9-24`).

`MarchingCubesExtractor.extract` (`Sources/MLX3DRuntime/MarchingCubesExtractor.swift:13-84`) subtracts `threshold` (default 25 on the image options, default 0 on the extractor itself) and reshapes to `[resolution, resolution, resolution]`. `useMetalMarchingCubes` false, the default, calls sibling `MarchingCubes.extract`. True calls `MetalMarchingCubes.extract` on the same field and bbox (`Sources/MLX3DRuntime/MarchingCubesExtractor.swift:43-54`). TripoSR then queries colors (`Sources/MLX3DRuntime/TripoSRMeshing.swift:98-132`). While a progress handler is set, density batches emit `volume`, the extract emits `meshing`, and color batches emit `colors`. A mesh with no faces from the high-level TripoSR image API throws `emptyMesh` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:393-395`). The extractor itself can return an empty `Mesh` (`Sources/MLX3DRuntime/MarchingCubesExtractor.swift:59-60`).

## Shap-E image to mesh

`imageToMeshShapE` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:315-350`) is separate from TripoSR. It validates the grid, optionally runs white-background `removeBackground` (`Sources/MLX3DRuntime/MLX3DRuntime.swift:429-451`), checks the Shap-E bundle (`Sources/MLX3DRuntime/MLX3DRuntime.swift:453-464`), and calls `ShapERuntime.generate(image:)`. Defaults are guidance 3, 32 steps, grid 64, seed 0, Metal marching cubes on, `progressInterval` 0, and white prep on (`Sources/MLX3DRuntime/MLX3DRuntime.swift:96-108`). It returns one `Mesh` per batch row. The progress handler receives Shap-E's phase and step. Partial meshes are forwarded only when `progressInterval` is greater than zero. `removeBackground` is not called from any TripoSR function. This static entry does not use `MLX3DSession`.

## Loaded-model session

`MLX3DSession` (`Sources/MLX3DRuntime/MLX3DSession.swift:38-396`) is the cache. The caller creates it and decides when to call `load`, `unload`, and `evict`. `imageToMesh(cgImage:)` on the session (`Sources/MLX3DRuntime/MLX3DSession.swift:188-202`) runs the same foreground cutout as the static entry, then reuses the cached TripoSR model. `imageToMeshShapE` on the session (`Sources/MLX3DRuntime/MLX3DSession.swift:264-279`) runs the same white prep, then reuses the cached Shap-E runtime. `imageToMesh(uiImage:)` renders an upright bitmap before that cutout (`Sources/MLX3DRuntime/MLX3DSession.swift:205-257`). A key is the backend plus the bundle URL plus auxiliary files the loader reads (`Sources/MLX3DRuntime/MLX3DModelKey.swift:18-54`). Shap-E weights come from the bundle directory. The BPE file is in the key because the cached `ShapERuntime` is constructed with it. TripoSR's key is the safetensors URL.

The cache (`Sources/MLX3DRuntime/MLX3DModelCache.swift:46-96`) returns a ready model without loading again, joins concurrent callers onto one in-flight task, and deletes a slot when the loader throws. `unload` bumps a generation counter. The in-flight task may still finish, including after cooperative cancellation, but it does not store the model, and every waiter throws `modelUnloaded` (`Sources/MLX3DRuntime/MLX3DRuntimeError.swift:51-53`). A load that starts after `unload` uses the new generation. `evict` removes only a ready model.

The session does not download files and does not pick a directory. Holding the session is what keeps the weights resident. Cutout and white-background helpers stay on `ImageBackgroundRemoval` and `MLX3DRuntime`; the session does not own that policy.

## Export and the example

`MeshExport` (`Sources/MLX3DRuntime/MeshExport.swift:81-162`) writes OBJ, ASCII PLY, and USDZ. The default OBJ has positions on `v`, `mtllib`, and `usemtl VertexColorAverage` (`Sources/MLX3DRuntime/MeshExport.swift:192-213`). The companion MTL stores the average albedo in `Kd` (`Sources/MLX3DRuntime/MeshExport.swift:216-229`). `objText` still emits the historical `v x y z r g b` extension and does not write an MTL (`Sources/MLX3DRuntime/MeshExport.swift:166-189`). Faces are 1-based in OBJ and 0-based in PLY (`Sources/MLX3DRuntime/MeshExport.swift:421-432`). USDZ is a 64-byte-aligned zip of a USD crate or USDA layer (`Sources/MLX3DRuntime/MeshExport.swift:128-144`, `Sources/MLX3DRuntime/MeshExport.swift:617-743`). Model I/O does not export the `usdz` extension. Per-vertex RGB is on the crate (`Sources/MLX3DRuntime/MeshExport.swift:345-388`).

`MeshExportOptions.upAxis` defaults to `.native` (`Sources/MLX3DRuntime/MeshExport.swift:67-79`). Native coordinates are Z-up: legs to back along Z, back toward +Z (`Sources/MLX3DRuntime/MeshExport.swift:43-54`). `.yUp` rewrites positions only while writing a file, `(x, y, z)` to `(x, z, -y)` (`Sources/MLX3DRuntime/MeshExport.swift:324-343`). Face indices are copied in order. `validatedFaceIndices` rejects a negative or out-of-range index (`Sources/MLX3DRuntime/MeshExport.swift:307-321`). Export does not apply pin offsets or scale.

`MLX3DCLI` dispatches `text` and `image` (`Sources/MLX3DCLI/MLX3DCLI.swift:39-58`). `MLX3DExample` only references `Mesh`, `MarchingCubes`, and `TripoSRModel` and does not load weights (`Examples/Integration/Sources/MLX3DExample/MLX3DExample.swift:7-17`).
